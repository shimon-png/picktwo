  - ZIP, sex (Male / Female / Prefer not to say) and age range (18–24 … 65+) are required. Signed-in users missing them are sent to `/onboarding`.
  - Tap-through tutorial overlay on `/vote` (localStorage `cp_tour_v1`); replay from You → Tutorial (`/vote?tour=1`).

- **#8 Contact us:** `/contact` form → `POST /api/contact` (IP rate limit, honeypot, min fill time) → `contact_message` table. Admin inbox at `/admin/messages` with unread badge. Optional email per message via `CONTACT_ALERT_EMAIL`.
- **#9 Guest gate, code sign-in, no repeats, changeable pick**
  - `guestVoteLimit` (economy config, default 5), counted per device incl. any account it was linked to. `castVote` throws `SIGNUP_REQUIRED`; deck shows `SignupGate`.
  - Sign-in: `POST /api/signin-code` → Auth.js Credentials provider `code` (`services/signin-code.ts`, `email_code` table, 10-min codes, 5 tries, hashed).
  - Feed filters voted battles by user and device; the deck also keeps voted/skipped ids in localStorage (`lib/seen.ts`). `linkDevice()` carries guest votes over after sign-up.
  - A tapped pick can be changed until Next.
- **#10 Drag-to-grow deck** — later **replaced** by throw-to-pick in #11 (Alex found it hard to use).
- **#11 "Prompt · Red & Blue" redesign + throw-to-pick**
  - Warm paper page, white cards, black ink, Instrument Serif 400 headings (never bold), Inter body, black pill buttons. Tokens in `src/app/globals.css` `@theme`; brand SVGs recoloured.
  - `SwipeDeck`: the photo lifts and follows the finger; past `THROW_FRAC` (0.32 of card width) or a fast flick it flies off, the vote counts, the result shows for `RESULT_MS`, then the next battle loads automatically. Tap still picks with results + Next.
  - Haptics via `navigator.vibrate` (Android only; iOS Safari can't vibrate from the web).
- **#12 Sign-up flow:** email → code → username → sex / age / ZIP (`POST /api/me/quick-profile`) → full page reload back to swiping. No other onboarding screens.
- **#13 Desktop fix:** photo no longer hangs after a long desktop drag; editorial vote card.
- **#14 Activity + profile**
  - Activity page: collapsible "Battles posted" / "Votes" / "Updates".
  - Profile photo upload in Settings (`POST /api/me/avatar`, Blob `avatars/`).
  - Location: Country select (ISO-2) → State select → City type-ahead (new `user.city`), data from `country-state-city` via `/api/geo`, validated server-side. Still optional.
- **#15 Site-wide restyle:** the Prompt look applied beyond the vote card (You, Post, Activity, Settings, sign-in, admin, legal, etc.).
- **#16 Username prefill:** suggested from the email on every profile-setup path.
- **#17 Photo safety**
  - `PhotoFlag` button on deck photos; `submitReport()` auto-hides at 2 flags for child safety / nudity, 3 for anything else (feature config).
  - Admin queue `/admin/reports`: reports grouped per battle, photos blurred until tapped, actions in `resolveReport()`.
  - Upload screening in `createBattle` → `screenPhotos()`: PhotoDNA hash match (ban + `csam_hash_match` report, **never deletes** the image, NCMEC duty), then OpenAI omni-moderation. Thresholds pure in `services/safety.ts` (`decideImage`): block = refuse + delete blob; review = battle created `HIDDEN` with an `auto_screen` report. Provider errors fail closed (review).
